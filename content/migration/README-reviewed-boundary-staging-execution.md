# Guarded reviewed-boundary staging execution (PR-0060)

This package fixes the scope at exactly 74 PR-0057 status-only operations. It discovers and hashes the PR-0055 through PR-0059 contracts in the generated manifest. The default `blocked` mode refuses before connecting. `fixture-apply` and `fixture-reconcile` are synthetic mechanics only; `staging-apply` and `staging-reconcile` require explicit authority paths, identity, execution identifier, and deliberate confirmation. Production apply and reconciliation are defined but always rejected.

Before connecting, the commands validate the closed authority chain: admitted evidence, redacted database attestation, collector-operator, technical-reviewer, and execution-authorizer attestations, unexpired/unrevoked decision, staging-only unused token, three upstream manifests, expected database identity, exact target set, hashes, and confirmation. After connecting, PostgreSQL 15 and the bound redacted staging/fixture identity are checked without logging credentials.

Application uses one transaction, a deterministic transaction-scoped advisory lock, and `SELECT ... FOR UPDATE` ordered by `run_id, book_id, segment_order, segment_key`. All rows preflight before the only permitted mutation, `approval_status = intended_approval_status`; `updated_at`, content, locators, hashes, metadata, and every other column are not explicitly updated. Each first application creates one deterministic, predicate-compatible PR-0055 audit event. Exact committed retry is a zero-write reconciliation; partial or inconsistent state fails closed.

Postflight requires 74 intended statuses, immutable projections and digest agreement, 74 matching application events, zero rollback events, correct counts, no unauthorized rows/columns, and a valid deterministic token-consumption receipt. Runtime evidence and the receipt are written only under `tmp/`. The independent reconciler reconstructs database and audit state read-only and does not trust executor output.

The PostgreSQL 15 workflow uses an ephemeral local service and synthetic authority only. It creates no staging authority. This PR does not execute against real staging, makes no production connection, and leaves production prohibited. No real staging evidence, attestations, decision, or token currently exists, so every committed authority and execution/readiness value remains false.

Rollback operations remain contractual only. Application authority never grants rollback; deliberate staging rollback needs a future distinct token or explicit emergency-authority package. PR-0061 requires deliberate real staging collection/admission, all three attestations, a fresh authorization decision and token, successful execution evidence, and independent reconciliation.
